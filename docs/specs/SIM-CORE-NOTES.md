## 3. Requirements

### SC-8 Crash recovery
- Without this, a command that crashes `step` would crash every recovery (Q-SIM-2).

### SC-10 Budgets
- A benchmark spike (1,000 entities, grid queries, one movement/sensor/combat pass, 500 viewer units) on the reference host decides before this spec is approved; objects stay unless the pass exceeds about 10 ms (Q-SIM-17: the spike also runs an idle case, 0 viewers and about 150 AI-only entities, to confirm the 24/7 idle load is small), in which case the hot fields move to NumPy arrays behind the same API.
- The spike is decided: Q-SIM-4 (objects behind a `World` API) was confirmed by the NX-345 reference run, 2026-10-20 (§8).
- Grid citation in the original SC-10: (§4 Sensing; NX-372, the Q-SIM-4 "optimize first, keep objects" decision).

### SC-11 Pause freezes the world
- `SYS_QUEUE_TIMEOUT` applies while paused (the last one so a timeout that raced the pause still lands; the runtime does not count paused time toward queue idleness, NX-371).

### SC-16 Replay scope
- a balance fix or a bug fix changes outcomes, so re-simulating an old log on new code is not promised.

## 4. World model (component-style, flat)

The paragraphs below are the former SIM-CORE §4 "In code now" and per-system narration, moved verbatim. They describe the code as of the move, with tracker and snapshot-format history. SIM-CORE.md §4 holds the rules a change must keep; the behaviour rules each system implements are owned by the spec named in its paragraph (GAMEPLAY, COMBAT, ECONOMY, FOG-OF-WAR, THREAT-DIRECTOR, STATE-MACHINES).

### Entity and world state
- **In code now (`nexus.core.world`, NX-121, NX-122):** `Entity` has `id`, `kind`, `side`, `owner_kind`, `commander_id`, `callsign`, `pos`, `vel`, `hp`, `path`, `last_node`, `state`, `fuel`, `orbit`, and for aircraft `rearm_milli`, `rearm_spent` and `stalled` (refuel progress, NX-123 part 2, snapshot format 11), and for facilities `base_id`, `variant` (the theater's catalog variant, e.g. `SAM`) and `emitting` (FOW-11: `None` for a kind that never emits, `true` emitting, `false` dark; snapshot format 8, NX-150 part 2); the other fields above join with the system that first reads them. `state` holds the STATE-MACHINES §4.1 states in code so far, for aircraft only (NX-368): `LANDED`, `EN_ROUTE`, `ON_STATION`, `RTB` (kernel-internal until a frame or event carries it; `None` for other domains). `fuel` is an aircraft's world seconds of flight left (a float, hashed at the 1e-6 step, ADR-0002), and `orbit` the centre an idle `ON_STATION` aircraft circles (hashed in mm); both `None` otherwise (snapshot format 5). `hp` is a real integer ≥ 1 for every kind since NX-124 (the catalog's, full at spawn; snapshot format 14), with `damage_state`, `alt_band` (an aircraft's default band), per-weapon `ammo` and `reload` lists in the unit's loadout order, and `wreck_left` (see Combat below). `World.respawn_left` maps a commander to the running ticks left of its respawn delay (GP-2), always ≥ 1; it is world state, in snapshots and `state_hash` (snapshot format 3). `World.reserve_queue` is the reserve queue (GP-3): the queued `JOIN` commands, head first, one per commander (U-4); it is world state too, encoded as each command's JSON data with sorted keys (snapshot format 4), and a snapshot that holds a commander twice is refused. `World.record_loss(commander_id)` sets it to `Rules.respawn_delay_ticks`; it is the hook the destroy and wreck paths call (NX-124), before `lifecycle` in their tick; `lose_unit` (the fuel crash, a unit lost at a captured base) calls it, and the shoot-down paths will. The `lifecycle` system counts every entry down by 1 per tick in commander-id order, not while paused (SC-11), and deletes it at 0, so a loss on tick L allows a JOIN on tick L + delay plus any paused ticks. `path` holds the remaining waypoints: node ids for GROUND, node ids or `Vec2` for AIR; a leading waypoint equal to `last_node` while the unit stands on that node counts as reached (a `shortest_path` route starts at its own node). `last_node` is the node a unit last reached or spawned at, so a GROUND unit is always on the road edge from `last_node` to `path[0]`. `World.stock` maps each finite-stock node to whole stock units (a SANCTUARY, the coalition's `haven` and the Static's rear source, is infinite by rule and absent); `start_campaign` fills it from the theater's `start_stock`. A cargo carrier (LOGI_TRUCK, ENEMY_CONVOY) has `cargo` (whole units aboard, else `None`), `unload_milli` (thousandths of a unit moved toward the next whole one, 0 to 999) and `delivered` (whole units unloaded in the current stop); all three are world state, in snapshots and `state_hash` (snapshot format 10, NX-123), and the loader refuses a format-9 snapshot. `World.owner` maps every theater node to its live owner (`COALITION`, `ENEMY` or `NEUTRAL`), starting from the theater's `start_owner`, and `World.capture` maps a node to its capture bar `CaptureBar{side, progress}` (progress in whole millionths of a percent, only while above 0); both are world state, in snapshots and `state_hash` (snapshot format 12, NX-125; the loader refuses format 11, and a bar with no owner entry for its node, with no progress or a full bar, or on its own side). `domain` is not stored: it comes from the unit catalog by `kind`. Static per-campaign data the kernel reads (`WORLD_DT`, `speed_mps` and `domain` by kind, the road graph, the role → kind map, the coalition sanctuary node, the logistics numbers (`Rules.supply`: each side's sanctuary, the nodes' starting owners, `logistics.node_max_stock` by node and its starvation floor, the cargo kinds, `logistics.truck_cargo`, `logistics.unload_rate` as thousandths per tick), `slots.max_live_per_commander`, `slots.respawn_delay_s` as game ticks rounded up, SC-12, `slots.max_viewer_units` and `slots.reserve_queue_max`, `min_speed_mps` and `fuel_s` per AIR kind, `air.bingo_reserve_frac`, `air.orbit_period_s`, `sensor.radius_m`, `stealth` and `sensor.passive_range_m` by kind (0 = none), `fow.paint_range_m`, the kinds that paint (RECON_UAV and ENEMY_RECON_UAV, named in `nexus.core.rules` until the catalog lists capabilities), `fow.sigint_range_mult`, `fow.sigint_refresh_s` as world ticks rounded up, `fow.sigint_cell_m` (which must divide the theater bounds) and `fow.sigint_size_m_min`/`_l_min`, the theater's masking regions rasterized to 1 km cells (Q-FOW-3), the AIRBASE and SANCTUARY node ids (`Rules.landing_nodes`: an aircraft lands at those its side owns now, `World.landing_bases(side)`, NX-125), every node's kind, the kinds whose catalog has weapons, the capture rules (`Rules.capture`, below) and the theater bounds; these keys are marked hot-reloadable but are not live yet: a config reload, when it exists, must rebuild `Rules` and log the change) is one frozen `nexus.core.rules.Rules`, held as `World.rules`; `make_rules` builds it from the loaded config. It is not world state, so it is in neither snapshots nor `state_hash` (`config_hash` covers it); `restore`/`recover` require it as `rules=` (`None` only for a world that never reads it) and re-attach it, refusing rules whose theater nodes differ from the snapshot's `World.owner` keys. `nexus.runtime.campaign_config.load_campaign_config` loads balance, the unit catalog and the theater from the shipped files (or given paths), and returns them with the `config_hash` and the `Rules`; the replay CLI uses it and refuses a snapshot whose campaign `config_hash` differs. `start_campaign(campaign_id, seed, config=None)` in the same module builds a new campaign's tick-0 world from it (the shipped files by default), stamped with its `config_hash` and with the `Rules` attached, and places the theater's `facilities` (NX-150 part 2): in theater-file order (so ids are deterministic), each is a `STATIC` entity at its base's position, on the base's starting side, `AI_GARRISON`-owned, `hp` null until combat (NX-124), with `base_id` and `variant`; RADAR_SITE and the SAM variant of AIR_DEFENSE_SITE start `emitting: true` (FOW-11, Q-FOW-10), every other facility `null`. Shipped-config golden cases start from it; `SimRuntime` refuses a world without rules, and a JOIN on such a world raises (SC-8 drops it). `CampaignStarted` lands with the campaign lifecycle (NX-126). `WORLD_DT` is computed once from `sim.tick_hz` and `sim.time_scale` in exact decimals (0.6 s at 6×). **Tasking state (NX-374, snapshot format 17):** `Entity.order` (`HOLD` from a JOIN with `hold`, `GOTO` from one with a node target; none when the board is in charge) and `Entity.job_id` (the job whose claim the unit holds), and `World.boards[side]`, each side's live jobs by id, with `World._next_job_id`; all in the snapshot and the hash, `load` refuses format 16 and checks every board (ids, dedupe keys, dependencies, claims against `job_id`). **Order hold state (NX-398, Q-SIM-110, snapshot format 25):** `Entity.order_node` (the node a JOIN's GOTO names, set at spawn, cleared when the order ends or a REBASE replaces it) and `Entity.held_since` (the running tick an armed unit began holding that node; None while not holding); `load` refuses either without order GOTO, and `held_since` without `order_node` or after the running clock. **Follow state (NX-374 part 2, snapshot format 18):** `Entity.order` also has `FOLLOW` (from a JOIN with a follow target), `Entity.follow_id` and `Entity.fired_by`, and `Job.entity`; `load` refuses format 17 (below). **Director state (NX-155, snapshot format 19):** `World.director[side]` (see the Threat Director paragraph below); `load` refuses format 18.

### Movement
- **Movement (SC-13 `movement` slot, NX-121):** in id order, each unit with a `path` spends `WORLD_DT` world seconds along it: AIR flies straight at `speed_mps`; GROUND drives road edges at `speed_mps × speed_mult` (GAMEPLAY §5). Time left after reaching a waypoint carries on to the next in the same tick; a reached waypoint is snapped to exactly. On reaching the last waypoint a ground unit stops (`vel` 0, `path` empty); an aircraft orbits or lands (below). `vel` is the heading to the next waypoint at the current speed, zero when idle. A follower's `World.speed_cap` (station keeping, formation speed; ground units only) lowers its speed before the road's `speed_mult`, and a ground unit whose path starts with the node it left drives back to it along the road it is on (a follower turning back to engage). While `clock_paused`, nothing moves (SC-11). A path is followed as given; JOIN assigns one (below), routing around a destroyed bridge comes with NX-124 / NX-126.

### Aircraft
- **Aircraft (same `movement` slot, NX-368, Q-SIM-38):** `speed_mps` is a top speed. `movement` picks the air rules by the kind's domain, and an AIR entity with no `state` is a bug (it raises); a snapshot whose entity has a `state` without `fuel` (or the reverse), or an `orbit` while not `ON_STATION`, is refused at load. A world with no rules moves nothing: only units with no path that are stateless or `LANDED` may be in it. Per tick, in id order: a `LANDED` aircraft with no path stays put (`vel` 0, no fuel burn). Otherwise, unless already `RTB`, the bingo check comes first: bingo when `fuel` ≤ the straight-line distance to the nearest landing base of its side ÷ `speed_mps` + `air.bingo_reserve_frac` × `fuel_s` (equality counts; ties by node id; a side with no landing base never bingos); at bingo its path becomes that base and its state `RTB`. A `LANDED` aircraft whose path is now just the landing base it stands on (a JOIN to its own sanctuary, or an order given at bingo) drops the path and stays landed without burning; any other path makes it take off (`EN_ROUTE`). Then it burns `WORLD_DT` of fuel (a constant burn per world second, a whole tick even on the takeoff and landing ticks) and moves or orbits (below). **Only after moving, fuel 0 is a crash** (owner, 2026-10-21): an aircraft that lands on the tick its fuel runs out stays landed (with fuel 0, which keeps it on the ground); any other is lost: after the loop, in id order, it is removed, `record_loss` starts its commander's respawn delay, and `UnitDestroyed{killer_id: null, assist_ids: [], side}` is emitted; the wreck and the crew-survival roll come with combat (NX-124). It flies its path at `speed_mps`. A path whose end is a landing base of its side (`RTB`, and any other path that ends there, as a later `!rtb` or move-to-base order will) lands it on arrival (`LANDED`, `vel` 0, `last_node` the base; it must end at the base node itself, so a `Vec2` waypoint after a base does not land); a path ending anywhere else puts it `ON_STATION`, orbiting a circle through the point it reached: entered along its last leg, turning clockwise on the map (so the centre of an eastbound arrival is one radius south), at `min_speed_mps`, one lap per `air.orbit_period_s` (PROPOSED 120 world s: radius = `min_speed_mps` × 120 / 2π, about 1.9 km for a jet and 380 m for a UAV). The orbit uses libm `atan2`, `cos` and `sin`, which are deterministic on one platform (ADR-0002); golden hashes are pinned to the CI platform. The circle's centre is clamped so the orbit stays in the theater bounds (a point within one radius of the edge snaps onto the clamped circle on the next tick; no strait-1 node is that close). A new path takes it off station (`EN_ROUTE`); `movement` keeps an `RTB` aircraft `RTB` whatever its path, so an order handler that gives an RTB aircraft a new path (NX-155, `!target`) must set it `EN_ROUTE` itself, which cancels the RTB. No airborne aircraft flies below `min_speed_mps`: it flies at `speed_mps` (≥ `min_speed_mps`, loader) or orbits at `min_speed_mps`; a clamp joins with the first slower speed (damage, NX-124; escort, NX-369). Bingo sits in `movement`, not `director`, because it is the unit's own fuel state, read and burned in the same slot; the Director's and Tasking Board's orders (NX-155) run before it. Paused: no burn, no orbit (SC-11). Refuel and rearm at a base are logistics (NX-123 part 2, `nexus.core.logistics`, below): a landed aircraft with no path at a landing base of its side buys fuel in the `logistics_capture` slot, and one ordered off with fuel at or below bingo stays on the ground (its order is dropped, as at its own base) and keeps refuelling; once it is above bingo a new order takes it off. An `RTB` aircraft whose path ends at a node that is no longer a landing base of its side (captured, NX-125) re-targets at once, in the same `movement` step, to the nearest landing base its side owns, by the bingo rule; with none left it flies on. Other RTB triggers (`!rtb`, munitions, mission-kill, idle retire) come with their items.

### Logistics
- **Logistics (SC-13 `logistics_capture` slot, `nexus.core.logistics`, NX-123; GAMEPLAY §5, GP-7, Q-GP-24, Q-SIM-48 to Q-SIM-54):** stock and cargo are whole integers and a unit leaves a source's stock as it becomes cargo, so their sum is conserved exactly; only a load at an infinite source adds, and a removed truck's cargo is lost. Stock also leaves for good as a spawn's loadout and as fuel: those debits are the `SupplyConsumed` events (open refuel stops included, `rearm_spent`), so stock + cargo + consumed is conserved. **Spawn:** a JOIN whose role maps to a cargo kind and whose target is a node *friendly* to the unit's side spawns the truck at its *source*, with `cargo` debited from that node at spawn. The source is the friendly node (never the destination) with a stock surplus, `stock - ceil(logistics.starve_threshold x node_max_stock)`, above 0, that has a road route to the destination, nearest by route metres (ties by node id); `cargo = min(logistics.truck_cargo, surplus)`, so a source never falls below its starvation floor. On a stocking run (NX-389, Q-SIM-102: the destination is at or above its floor, below `ceil(logistics.stock_target_frac x node_max_stock)` and has no damaged facility of the side) the surplus is counted above the source's own target instead (`logistics.keeps`), at spawn and again when a board truck loads at its source. With no such node the side's SANCTUARY loads a full `truck_cargo`. Path: the road route source to destination. A neutral or enemy target, a node that holds no stock, or a null target or `hold` is a capture run or Holding: the truck spawns at the sanctuary with `cargo` 0 (the Tasking Board picks a job later, NX-155). Every other kind forward-deploys (JOIN, above) with `cargo` `None`. "Friendly" is the node's live owner (`World.owner`; capture changes it, NX-125). The Static has its own infinite rear source, `enemy_rear_source` (`static-rear`, Q-SIM-48), joined to its HQ by road and never capturable (N-4); a convoy of the Static (ENEMY_CONVOY, the same mechanic) is spawned directly by tests until the Director lands (NX-155). **Unload:** each running tick (not while paused, SC-11), in id order, a carrier with `cargo` > 0 standing at the end of its path moves `logistics.unload_rate x WORLD_DT` into its node: it adds the per-tick rate (whole thousandths) to `unload_milli`, moves the whole units, capped by its cargo and the node's room (`node_max_stock` minus `stock`), and keeps the fraction. At a full node, and when its cargo is 0, it stays parked, Holding (the retire is GP-5 / NX-324). A truck sent by its operator's command does not divert from a full base (Q-SIM-50, owner amendment 2026-10-21); the divert for AI and Tasking Board jobs lands with the board. **Lost destination:** a truck standing at a node no longer friendly to its side with cargo left drives to the nearest friendly base (a node with a stock maximum above 0, not a sanctuary) that has room, else to the nearest friendly base, else stays put, and unloads on arrival as above. **Event (lead decision, NX-123):** a stop at a node ends when the cargo reaches 0, the node reaches its maximum, or the truck drives off (lost destination); it then emits one `SupplyDelivered{node_id, amount, carrier_id, commander_id}` (CONTRACTS §6, `contracts/events/supply_delivered.json`) with `amount` = the units unloaded there during the stop, and none if that is 0. It is emitted for both sides; the public-view drop of ENEMY deliveries is downstream. `delivered` is reset when the event is emitted. A truck removed mid-stop emits nothing (superseded: `world.lose_unit` reports the open stop first, Defense below; SIM-CORE §4 Logistics 10). `UnitSpawned` has no cargo field, only `loadout: FULL`. **Refuel (NX-123 part 2, Q-SIM-51, Q-SIM-53):** each running tick, in id order, after the trucks (no wall time, not while paused), an aircraft that is `LANDED` with no path at its `last_node` buys fuel when that node is one of its side's landing bases (AIRBASE or SANCTUARY, `World.landing_bases`; nowhere else, Q-SIM-42), and its kind's `loadout_cost` is above 0. Per tick it buys up to `logistics.rearm_rate x WORLD_DT` stock (whole thousandths, `Supply.rearm_milli`; the loader refuses less than 0.001 per tick), and one stock buys `fuel_s / loadout_cost` world seconds, so only the missing fuel is paid for: a full refill costs exactly `loadout_cost`. The last purchase is the exact remainder and sets `fuel` to the target (a conversion within 1e-6 thousandth counts as exact). A finite base is debited as the thousandths owed (`Entity.rearm_milli`, carried) reach whole units, never beyond its stock, so units debited = thousandths bought / 1000. Below its starvation floor (`stock` < `ceil(starve_threshold x max)`, checked each tick) the target is `logistics.starved_loadout.fuel_frac x fuel_s`, not `fuel_s`; at the sanctuary (infinite) the same rate runs with no debit and no cap. At 0 stock the aircraft gets nothing; the tick it first cannot buy it emits `RearmStalled{entity_id, node_id}` once (`Entity.stalled`; a resupply then a new stall emits again). A refuel stop ends when the aircraft is full or at the cap, stalls, or is no longer landed there (it takes off, or the node stops being friendly); it then emits one `SupplyConsumed{node_id, amount, cause: REARM}` with the whole units debited in the stop (`Entity.rearm_spent`), none for 0 (the node is `last_node` when the stop ends, which only differs if a takeoff reaches another node within one tick). Snapshot format 11 adds `rearm_milli`, `rearm_spent` and `stalled`; format 10 is refused.

### Combat
- **Combat (SC-13 `combat` slot, `nexus.core.combat`, NX-124 part 1; COMBAT CB-1 to CB-7 and CB-9, Q-SIM-65):** each running tick (not while paused, SC-11), in this order: weapon `reload` and `wreck_left` timers count down one tick; then new shots fire, entities in id order, each ready weapon (rounds left, no reload) in catalog order at the best tracked target (`threat` descending, distance, id; only contacts the shooter's side tracks now, the weapon's `targets`, its `bands` for an AIR target, a LANDED aircraft being a GROUND target with no band and evasion 1.0 that, as a shooter, takes no AIR target (COMBAT CB-7, Q-MV-14, Q-MV-18, Q-MV-19), within `range_m`; not a target whose shots in flight already cover what it has left in expected damage, the overkill check, `combat.overkill_check`, Q-TD-73, NX-468: per-tick scratch summed over `World.shots` in `(impact_tick, id)` order, never world state), spending a round, starting the reload and storing a `Shot` in `World.shots` (sorted by `(impact_tick, id)`, ids from `World.next_shot_id`); (each ready weapon's best target is found with per-side, per-threat-level uniform grids searched in growing radii, SC-10, equal to a full scan) then every shot due lands in that order: a missing shooter or target, a lost track or an out-of-envelope target is a miss with no draw, otherwise `Pk = min(pk_cap, base_pk x track x range x evasion x masking)` and one `combat`-stream draw; a hit takes `max(1, floor(damage x (1 - armor)))` hp (and is kept in `Entity.hits` for `combat.assist_window_s`, running ticks) (`armor` an exact decimal), moves the damage state by whole-hp thresholds (`ceil(fraction x max hp)`), and a unit at 0 hp, or an airborne aircraft that reaches Disabled, is removed with `UnitDestroyed{killer_id, assist_ids}` (the other shooters inside the window, sorted, at most 32; Q-SIM-66); a facility floors at the Disabled threshold (default; Q-CFG-16 option `combat.facility_indestructible`: off, a facility at 0 hp is destroyed and every side drops its contact and marker of it); a non-facility (a LANDED aircraft included) that becomes Disabled stops and is removed `combat.disabled_timeout_s` later with `UnitDespawned{WRECKED}`. `impact_tick`, reloads and wreck timers are on the campaign clock (running ticks), so a pause freezes them. Events are built with `model_construct` in the order fired, impact, state change, destroyed. Disabled units do not move, fuel up or unload (their cargo is lost with the wreck), do not contest a capture and cannot escape a flipped base. A Disabled facility is not a valid target and, like a dark one, senses, emits and listens for no one (FOG-OF-WAR FOW-11). It stays Disabled until repaired back up to the restore line (`combat.facility_restore_frac`, shipped: the Mission-kill line; Q-TD-86, NX-472). **Structures (NX-124 part 3, CB-10):** a weapon with the STRUCTURE target and no valid unit target in range fires at the nearest enemy-owned node (never the Static's rear source, nor one held at its idle floor) with defense HP above 0 within range (ties by node id); with `combat.strike_structure_first` (NX-440, Q-TD-55; shipped on since NX-412 part 5b, Q-TD-79) a unit holding a STRIKE claim on such a node fires at it before any unit target; the `Shot` carries `node` and no target entity, `WeaponFired` and `WeaponImpact` carry `target_node_id` with a null `target_id`, and a hit removes the weapon's full `damage` from `World.defense_hp` (armor 0, evasion 1.0, no masking, Q-CBT-22); a shot fizzles with no draw if the node changed hands, is at 0 or is out of range. See Defense below.

### Capture
- **Capture (SC-13 `logistics_capture` slot, after logistics; `nexus.core.capture`, NX-125; GAMEPLAY §8, STATE-MACHINES §4.2, Q-SIM-56, Q-SIM-57):** each running tick (not while paused, SC-11), for each node but a SANCTUARY or BRIDGE (never captured, N-4), in id order, from the units within `capture.radius_m` of it (a scan of every entity per node; no RNG). **Who counts:** GROUND units are capturers, a logistics unit weighing `capture.logi_weight`; airborne aircraft and facilities never count (N-3, Q-GP-38; airborne aircraft: default, Q-CFG-16 option `capture.air_counts`). A GROUND unit whose catalog has weapons and that is not Disabled is combat-capable. A defender that cannot contest (an unarmed or Disabled ground unit, or an aircraft LANDED at the base) applies `capture.garrison_mult` (x3 on the capture time); an owner with no unit at the base applies `capture.empty_base_mult` (x0.5); a NEUTRAL node uses neither. **The bar:** per node, the side filling it and its progress as an integer of millionths of a percent (a full bar is 100,000,000), so thresholds and decay are exact. A side that is not the owner and has capturers is *free* when the other side has no combat-capable unit there. With no bar, one free side starts it (`CaptureStarted{node_id, side}`); with two free sides (a neutral node, both unarmed) the side with the larger capture weight (logistics units count `capture.logi_weight`) starts it and an exact tie starts nothing (Q-SIM-59); with none, nothing starts. A bar fills while its side is free and drains by `capture.decay_per_s` x `WORLD_DT` otherwise, abandoned or contested by a combat-capable unit (owner, 2026-10-21, Q-SIM-23); at 0 it is removed, the owner stays and the start rule applies again. A tick adds `max(1, round(100,000,000 x WORLD_DT / time))` with `time = max(capture.min_time_s, capture.time_s x capture.time_mult.<kind> x quiet_mult(v) / n^(capture.multi_unit_exponent + capture.extra_exponent.<kind>) x modifier)`, `<kind>` the node's kind for whichever side captures (NX-490: an HQ is very hard to capture, hardest alone; every other kind 1.0 and 0), `n` the weighted capturers (1 per unit, `logi_weight` per logistics unit), `v` the live viewer units as JOIN counts them (`World.viewer_units`), and `quiet_mult` rising linearly from `capture.quiet_floor` at 0 to 1.0 at `capture.quiet_ref` for the coalition only (Q-SIM-26; the enemy's is 1.0); `n^exponent` uses libm `pow`, pinned to the CI platform like the orbit (ADR-0002). At 100% (N-1: one bar, one test per node per tick) the owner becomes the capturing side and the bar is removed, and in the same tick: `NodeCaptured{node_id, from, to, participant_commander_ids}` is emitted (participants: the commanders of the capturing side's units in radius, sorted, no duplicates); the facilities with that `base_id` switch side keeping their damage and everything else (Q-GP-25; the fog follow-ups are under Sensing). **Amended by NX-471 (Q-TD-78; in code):** with `capture.facilities_disabled` on, each facility also drops to min(hp, floor) and DISABLED, its repair carries reset and `Entity.seized_carry` set to 0, before its fog hand-over (GAMEPLAY §8 "Facilities at a captured base"); the previous owner's mobile units in radius, in id order, escape or are lost (Q-SM-10, Q-GD-32): a GROUND unit (a loaded truck included, its cargo stays aboard, and an open unloading stop ends with its `SupplyDelivered`) takes the road route to the nearest base its side owns (any owned node but a BRIDGE; ties by node id), from the node it is heading for if it is on the road, else from where it stands; an aircraft LANDED there whose fuel covers the straight line to the nearest landing base its side still owns, at top speed, takes off `RTB` to it; anything else is removed, `record_loss` starts a commander's respawn delay and `UnitDestroyed{killer_id: null, assist_ids: [], side}` is emitted, like the fuel crash. Airborne aircraft near the node are not at the base and are left alone. The crew-survival roll waits for combat (NX-124). A flip from NEUTRAL resolves no units (there is no losing side). The stock at the node stays with the node. Night cap and last base (Q-TD-93, NX-474; Q-TD-103, NX-481): the Static's flip spacing is `night_cap_ticks` fading linearly to 0 at `capture.quiet_ref` viewer units (integer, `director.night_spacing`), and with the idle floor on, the only strategic node the coalition holds, whichever it is, starts and fills no bar (a running one still decays or drains); ownership is read per node during the id-order pass, so a flip earlier in the same tick counts. The exception is the `forward_airbase` at 0 live viewer units: the idle floor wins and the node is skipped, so its bar neither starts, fills nor decays (Q-GP-28). Not in code yet: the base defense-HP gate (Q-GD-18, with combat), `CaptureProgress` (the spec gives no cadence), Disabled units, bridges. ### Defense
- **Defense (NX-124 part 3, `nexus.core.defense`; GAMEPLAY §8 and §9, COMBAT CB-10, Q-GD-18, Q-SIM-71, Q-TH-7):** `World.defense_hp` is each defended node's whole hp (every kind but BRIDGE; `capture.defense_hp.<kind>`; an owned node starts full, a NEUTRAL one at 0), with `defense_drain` (the starvation carry, hp x ticks below one game minute of ticks) and `defense_down` (the nodes that announced `NodeDefensesDown` and are not yet back at full); all in the snapshot and hash. **Rebuild:** `logistics` adds `logistics.defense_repair_hp_per_stock` (2) per whole unit it unloads into a node, up to the maximum, in that tick. At a finite-stock node whose stock is full but whose defenses are not, a truck keeps unloading at `unload_rate` and each whole unit goes straight into the defenses instead of the stock (counted in `Entity.defended`); the stop reports its units as `SupplyDelivered` and one `SupplyConsumed{REPAIR}` of the units spent on defenses at its end, so stock + cargo + consumed stays exact. With room in stock, stock is filled first; with both full the truck parks with its cargo. A truck lost mid-stop (destroyed, or lost at a flipped base) reports its open stop first (`SupplyDelivered`, then `SupplyConsumed{REPAIR}`, before `UnitDestroyed`), so the books still balance. Restore refuses an entity whose `last_node` or a path waypoint is not a theater node. A sanctuary takes no cargo (parked trucks repair it). **Drain:** after `logistics` in the `logistics_capture` slot, a node with finite stock below its starvation floor adds `logistics.starve_hp_drain_per_min` (5) to its carry each running tick and loses `carry // ticks_per_minute` hp (600 ticks at 10 Hz); the carry stays while the node is not starved and clears at 0 hp or a flip. **Events:** `NodeDefensesDown` when hp reaches 0 (from fire or the drain) unless already flagged down; `NodeDefensesRestored` only when a rebuild takes a flagged node to full, so a node flapping around 0 emits one pair per cycle; a node that was never down (a NEUTRAL node, one that just flipped) emits nothing as it builds up. A hit that takes the coalition sanctuary below full emits `ThreatAdaptation{SANCTUARY_AT_RISK}`, once per drop from full (NX-493, Q-TD-122; GAMEPLAY §1b `defend:`). A flip sets hp, carry and flag to 0 for the new owner, with no event. **Sanctuary repair (Q-SIM-71):** in the same slot, each logistics unit of the owning side parked at its side's sanctuary (no path, `last_node` the sanctuary, not Disabled) adds `capture.sanctuary_repair_hp_per_s x WORLD_DT` in thousandths of an hp per tick (600 at the shipped rate) to the sanctuary's `defense_drain`, which for a sanctuary is the carry in thousandths (it never starves); whole hp are rebuilt up to the maximum with no stock debit, and the carry clears at full; the Restored rule above applies; nothing while paused. **Idle floor:** with `World.viewer_units() == 0` (live COMMANDER-owned units; AUTO units will not count once the AUTO state exists, Q-ALN-8/9) a hit cannot take the coalition sanctuary below 1 (default; Q-CFG-16 options `campaign.idle_floor.enabled` and `sanctuary_min_hp`). Restore checks hp against the maximum, the carry against a minute, and the flags against the hp (`defense.validate`, from `recovery.restore`).

### Bridges
- **Bridges (NX-373 parts 1a and 2, `nexus.core.bridges`; STATE-MACHINES §4.3, COMBAT CB-10, Q-SIM-105 to Q-SIM-107):** `World.bridge_hp` (every BRIDGE node, id order, whole hp, starting at `logistics.bridge_hp`), `World.bridge_down` (the bridges that reached 0; a bridge leaves it only when repaired to full) and `World.bridge_repair` (each bridge's truck repair carry in thousandths of an hp) are state, in the snapshot and hash (snapshot format 26; older formats are refused). Fire: in `combat`, a unit whose own STRIKE claim (`job_id` on its side's board) is on a bridge shoots it (never one whose GOTO order's `order_node` is the bridge: that holds and defends it, Q-SIM-124, NX-408) with a STRUCTURE weapon, while it has hp and is not down (a bridge under repair is never struck again), after unit targets and before the node fallback; the hit is a node shot (`Shot.node`), takes the full damage down to 0 and counts no provocation; a shot landing at 0 fizzles with no draw. At 0 the bridge joins `bridge_down` and `BridgeDestroyed{node_id, by_id, lost_ids}` is emitted once. Collapse (NX-400, Q-SIM-112): then, before the reroute, `bridges.collapsing` names in id order every GROUND unit on the bridge's edge (off its end nodes) within `logistics.bridge_collapse_radius_m` of the cut point along the edge (`lost_ids`), and each is removed by `lose_unit` with the shooter as killer, no assists and `cause: BRIDGE_COLLAPSE` (cargo lost, CB-8 roll), a victim of the other side passing through `provocation.suffered_hit` as a kill. `bridges.blocked(world)` is the one `blocked` set every road search passes (`tasking`, `handlers`, `logistics`, `follow`, `launch`), so a cut edge is in no path computed after the tick (B-1). Paths already set (part 1b, Q-SIM-108): the hit that downs a bridge calls `bridges.reroute`, which, in id order, turns back each GROUND unit still short of a down bridge's cut point (the bridge's position projected on its edge) to the node it came from, and replans a later hop over a cut edge from the node before it, by `roads.shortest_path` to the path's last node, a coalition patrol through held nodes only and a Static patrol without its `via` (no route: it stops at that node, keeps its claim until `tasking.claim_lease_s` releases it, and a loaded truck unloads there if the base is friendly, else `_divert` sends it on); a unit at or past the cut point and beyond the collapse radius carries on, aircraft are untouched, and `follow._ends` never offers a follower the end across the cut. The STRIKE verdict on a bridge is DONE once it is down. Repair (part 2, SC-13 `logistics_capture` slot, after the drain and before capture; `bridges.repair`): each running tick, every carrier of either side with no path, not Disabled, standing on a bridge's *stop* (`RoadGraph.stops`: the bridge's position projected on its road, the cut point; a path ending in the bridge's id ends there, `step._waypoint` and `_arrive`, with `last_node` left at the bank it drove out from) adds `Supply.bridge_repair_milli` thousandths of an hp, derived by the loader from `logistics.bridge_hp × WORLD_DT / (bridge_repair_time_s × truck_bridge_repair_mult)` (60 a tick shipped; below 1 the config is refused); whole hp move from the carry, capped at the maximum (B-2); at full the carry is 0, and a down bridge leaves `bridge_down` with `BridgeRepaired{node_id, by_id}` (the lowest-id carrier there). A truck parked at a stop does not unload into its bank (`world.on_node`). A unit leaving a repair (claim ended or released), or any not-Disabled, non-following ground unit without a repair claim at a board pass, leaves the stop toward its bank (`world.leave_stop`, from `release_claim`, `tasking._end` and `tasking.run`). `bridges.reroute` plans a path to a stop to the bank before it and keeps the stop after a new route. Restore checks that the keys are the theater's bridges, 0 <= hp <= max, 0 hp is down, a down bridge is below full, and a repair carry is below 1000 and 0 at full (`bridges.validate`, from `recovery.restore`). `reroute` also runs after a capture flip with `taken=node`: a supply run or repair crew whose road enters that node replans the same way (a run's destination exempt unless it is the source of an empty pickup leg, a crew's bank not; NX-413).

### Campaign
- **Campaign (SC-13 `objectives` slot, after capture; `nexus.core.campaign`, NX-126; GAMEPLAY §9, STATE-MACHINES §4.4 and §4.5, Q-SIM-60 to Q-SIM-62):** the **campaign clock** is `Campaign.running_ticks`, the ticks the world was not frozen (`World.frozen`: paused, or ended); `Campaign.tick` counts every tick, so a paused or ended world still advances `tick` (C-1). Game time is running ticks: `campaign.time_limit_h`, `victory_hold_min` and `objective_period_min` become ticks at config load (SC-12) in `Rules.campaign`. Each running tick the slot adds the tick to the clock, adds each side's count of held **strategic nodes** (AIRBASE, FOB, PORT; never BRIDGE, SANCTUARY or HQ) to its running sum (`held_ticks_coalition`, `held_ticks_enemy`, integers), resolves the active objective, then checks the end, in this order: **victory** when the coalition owns `enemy_hq` (default; Q-CFG-16 option `campaign.victory.hq_capture`), or has held at least `campaign.victory_node_frac` of the strategic nodes (an exact `Fraction` of the decimal in the file) for `victory_hold_min` running ticks in a row (`hold_ticks`; a dip resets it; NX-412 part 4, ECONOMY EC-9: `VictoryHoldStarted{node_ids, ends_at_tick}` on the run's first tick and `VictoryHoldBroken{node_id}`, the lowest-id hold node lost, when it breaks, none when the campaign ends during it; `Campaign.hold_nodes`, the held strategic nodes while the run lasts, is state, snapshot format 31, and enters the `EnemyView` as `SideView.hold`; NX-466, ECONOMY EC-9b: with `campaign.victory.pause_on_pressure` (default true) a running hold under the other side's pressure gains nothing that tick and does not reset (`Campaign.hold_paused_ticks`, snapshot format 38); NX-489, ECONOMY EC-9a, Q-TD-126: with `campaign.victory.hold_break: decay`, the default, a break keeps the progress `hold_ticks` instead of resetting it, so "in a row" means "since the last reset": the kept progress drains over `Campaign.hold_broken_ticks`, the running ticks since the break, along floor(`decay_slow_rate` x min(t, S) + `decay_fast_rate` x max(0, t − S)) with S `decay_slow_min` in running ticks, computed in closed form from exact `Fraction`s; the hold resumes from what is left when the share is back, and `VictoryHoldReset{DECAYED|REPAIRED}` ends it at 0 or when the Static owns a node of `Campaign.hold_broken_nodes` at full defense HP (`reset_on_repair`); both fields are state, snapshot format 37, and a decaying hold is not in `SideView.hold`; `hold_break: reset` is the old rule); else **defeat** when the coalition sanctuary's defense HP has been 0 for `campaign.defeat.hold_min` running ticks in a row (`Campaign.defeat_ticks`; a repair resets it; while no viewer unit plays and the idle floor is on it is held and `Campaign.defeat_idle_ticks` counts the empty stretch, and once that reaches `campaign.defeat.hold_min` the run resets, so a short gap resumes it and a viewer who joins after a long one starts a full hold, Q-TD-95, snapshot format 36; `CampaignEnded{DEFEAT}`, winner ENEMY, score as at the limit); else the **time limit** when `running_ticks` reaches `time_limit_ticks`. Only the coalition can win mid-war: the Static has no domination win (Q-SIM-64); it wins only at the time limit by score (`winner: ENEMY`). **Score** per side = `campaign.score.average_weight` x its summed held counts / (strategic nodes x running ticks) + `final_weight` x its share of strategic nodes at the final tick + `objective_points` x completed objectives (coalition only: objectives are the coalition's), as an exact `Fraction`; the event carries `float(score)`. The higher score wins; an exact tie is `winner: null` (Q-GP-10). `CampaignEnded{result, end_tick, score, winner, nodes_held_pct}` is emitted once (C-2) and sets `Campaign.ended`: the world is then frozen (movement, sensing, logistics, capture, lifecycle and this slot return early) and `apply_commands` rejects every later command, in the same tick too, with `CAMPAIGN_NOT_RUNNING` (C-3). SC-15 (Q-SIM-15) exempts the SC-11 safety actions (`STAFF_BAN`, `FORGET`, `STAFF_KILL_SWITCH`): none exists in code yet, so today every command is rejected; whoever adds one exempts it in `apply_commands`. `nodes_held_pct` and the Hud's percentages are rounded to the nearest whole percent, halves up. **Staff commands** (`handlers.py`): `STAFF_CAMPAIGN_PAUSE` sets `clock_paused`, `pause_reason`, `pause_sub_reason` and emits `CampaignClockPaused`; checked in order `INVALID_PAYLOAD` (a `sub_reason` with a category other than STAFF), `REASON_REQUIRED` (a STAFF command with a blank note), `ALREADY_PAUSED`. `STAFF_CAMPAIGN_RESUME` clears them and emits `CampaignClockResumed` with the pause's reason and sub-reason (`NOT_PAUSED` when running). `STAFF_CAMPAIGN_END` emits `CampaignEnded{ABORTED}` from Running or Paused; any objective still active expires first in that tick (also at a victory or time limit), and with no campaign rules it ends with zero scores and 0 % nodes held. The kernel only validates payloads; who may send which is ADMIN-RBAC's (outside the kernel), and it does not check that `issuer` matches `source`. **Timed objectives** (`objective` stream; `World.objective`, the active one): in `timed` mode there is exactly one active objective while the campaign runs and a frontline exists (O-1): the first is announced on the first running tick, and the next in the tick the previous resolves, so `objective_period_min` is an objective's lifetime and an early completion starts the next at once. The pick is uniform (`randbelow`) over the sorted candidates: nodes that are not SANCTUARY, BRIDGE or the enemy HQ and have a road neighbour (BRIDGE nodes aside) owned by another side than their own; with none, nothing is announced, no draw is made and it is retried next tick. `ObjectiveAnnounced{objective_id, node_id, deadline_tick}`: ids are sequential from 1; `deadline_tick` is on the campaign clock (running ticks, the Hud's `elapsed_ticks`), not `tick`. A node the coalition does not own is a **capture** objective, completed in the tick the coalition's `NodeCaptured` for it is emitted (participants: that event's); a coalition node is a **hold** objective, completed only if the coalition owns it when the deadline arrives, however often it changed hands meanwhile (Q-SIM-61; participants: the coalition commanders with a ground unit, or an aircraft LANDED, within `capture.radius_m` of it then, sorted, no duplicates, possibly none). Otherwise `ObjectiveResolved{EXPIRED}` at the deadline. A pause freezes it (O-2). `off` mode has none. No merit yet (progression). **Momentum** (Q-SIM-60) is the pure `momentum(world)`, not stored: `Momentum(momentum_pct, nodes_held_pct, supply_pct)` with `momentum_pct` = `campaign.momentum.nodes_weight` x the coalition's share of strategic nodes + `supply_weight` x its supply fill (the coalition's finite-stock bases' stock / their max stock, 0 with none), exact `Fraction` arithmetic, rounded half up, clamped to 0 to 100. All of it is world state, in snapshots and `state_hash` (snapshot format 13; a format 12 snapshot is refused): the `Campaign` clock, pause reason, `ended`, `hold_ticks`, the two held sums, `objectives_issued` and `objectives_done`, and the active `Objective`. Not in code yet (defeat and the sanctuary's HP and the idle floor were on this list, superseded: they are in code, as described above): `STAFF_CAMPAIGN_*` auto pauses (runtime), extensions and `campaign.max_extension_h`, admin-set objectives, merit for objectives, `CampaignStarted` and `AARStarted` (runtime), the Hud frame.

### Rearm stop
- **Rearm stop (NX-124 part 2, `nexus.core.rearm`, called from `logistics` for every entity not unloading cargo; Q-SIM-68):** supersedes the fuel-only refuel above. A unit is stopped at a base when it is an aircraft LANDED with no path at a landing base of its side, a GROUND unit with no path standing on a friendly non-BRIDGE node, or a facility at its own base while that base has no capture bar (not contested). A Disabled non-facility never restocks. A kind with `loadout_cost` 0 (the trucks) has nothing to refuel or arm but repairs for free (`loadout_cost` x the hp share is 0); a facility restocks at `logistics.facility_rearm_cost`. Three lines, in this order, all integers except fuel: **fuel** (aircraft) and **ammo** share the per-tick budget `Supply.rearm_milli`; a full tank costs `loadout_cost` for a kind with no rounds and half of it otherwise, a full load of rounds the other half (all of it for a kind with no fuel); the ammo share is the average over the n weapons of each weapon's missing share (rounds missing / that weapon's full load, Q-SIM-69 lead decision), so a weapon with `full` rounds charges `price / (n x full)` a round and a missile costs far more than a gun round. The budget buys, in loadout order, every round it can afford, so cheap gun rounds fill while a missile is still being saved for; `Entity.ammo_credit` (stock-thousandths x n x lcm of the full loads) carries the part bought and makes the cost exact. A facility pays `logistics.facility_rearm_cost` (10) for a full reload of all its weapons, by the same rule, at the same `rearm_rate`, while its base is friendly with no capture bar and the facility is not Disabled (a Disabled facility does nothing until repaired back up to the restore line, `combat.facility_restore_frac`, shipped: the Mission-kill line; COMBAT CB-9, Q-TD-86); free at a sanctuary; a starved base refills only guns. A starved base fills fuel to `starved_loadout.fuel_frac` and only gun rounds (`projectile_speed_mps` null: `starved_loadout.secondary_ammo` 0). **Repair** runs at `logistics.repair_rate.<node kind>` hp per world second (`Supply.repair_milli`, carried in `Entity.repair_milli`); a unit pays `loadout_cost` x the hp share repaired (`num/den` = cost / max hp), a facility 1 stock per `logistics.facility_repair_hp_per_stock` hp, owed in `Entity.repair_debt` (1/den stock-thousandths); a starved base still repairs; the SANCTUARY is free. A seized facility (NX-471) gets the base rate ÷ `capture.seized_repair_slowdown` through `Entity.seized_carry` until it is back at the restore line (GAMEPLAY §8). Snapshot format 39 adds `Entity.seized_carry` (null, or 0 ≤ carry < S on a Disabled facility with the switch on); `combat.validate` refuses it anywhere else and format 38 is refused. Every stock-thousandth drawn goes through `rearm_milli`, so whole units debited = thousandths bought / 1000, and a base never sells past its stock. At a stop's end, `SupplyConsumed{REARM}` carries the whole units spent on fuel and rounds and a separate `SupplyConsumed{REPAIR}` the units spent on hp (`Entity.rearm_spent`/`rearm_milli` and `repair_spent`/`repair_owed`, both debited from the one stock; a base never sells past its stock); `RearmStalled` once when something is wanted and nothing could be bought. A unit removed mid-stop (any `lose_unit`: shot down, fuel crash, lost at a flipped base; or a wreck timing out) first reports its pending `SupplyConsumed{REARM}` and `{REPAIR}`, so stock + cargo + consumed is conserved exactly across losses. Auto-RTB is edge-triggered (COMBAT "In code now (part 2)"), not checked each tick. A restored world is refused (`combat.validate`) if spend counters or a stall flag sit on an entity with no node to report them at (they may legitimately outlive a stop by one tick: `restock` flushes them, and `capture`, which runs after it, can end the stop first), repair progress sits at full hp, or `ammo_credit` is above the bound (below `n x lcm` once every round is back, else below the dearest round, `price x lcm / smallest load`). `ammo_credit` is a msgpack integer, so the loader refuses a loadout whose `2 x price x lcm` of its full loads reaches 2**62 (price at most 1000 x the dearest cost; shipped loads of 400 and 8 give lcm 400, eight coprime loads of 61 to 97 would not fit). Snapshot format 15 adds `ammo_credit`, `repair_milli`, `repair_debt`, `repair_owed`, `repair_spent` and the downed-crew markers (`crew_markers`, `next_marker_id`); format 14 is refused.

### Tasking Boards
- **Tasking Boards (SC-13 `director` slot, before `movement`; `nexus.core.tasking` and `tasking_gen`, NX-374 part 1; GAMEPLAY §1b TB-1 to TB-10, Q-SIM-73):** every `tasking.reeval_every_ticks` running ticks (the pass at running tick `n = running_ticks + 1` runs when it divides `n`; never while frozen, SC-11), for COALITION then ENEMY: orders end (a GOTO when its unit arrived; an armed unit, one with a round left, that is at its order's node, `Entity.order_node`, first holds it, `Entity.held_since`, snapshot format 25, until it has a path again (bingo, RTB), runs out of rounds, lands, is Disabled, is given a REBASE, or has held `tasking.order_dwell_s` (a hold on a down bridge goes on, Q-SIM-127); one stopped short of the node hands back as before; Q-SIM-110, NX-398), claims are settled (released, made ACTIVE, or timed out after `tasking.claim_lease_s`) and each job's outcome decided, the side's jobs are generated from its `SideView` and its own state (resupply, defend, strike, assist objective, scout; rules in `tasking_gen`'s docstring, TB-9) and posted by dedupe key, and the side's idle units are assigned in id order, the best job first. A spec naming the job it waits for (`JobSpec.after`, a dedupe key; TB-8, NX-373 part 2) depends on that live job, and an open unclaimed job that gains such a dependency is ended (EXPIRED) and posted again with it, so its `JobCreated` names the dependency. A pass adds about 2 ms to a pass tick at 1,000 entities (measured on the dev host: pass ticks 8.2-8.5 ms against 6.2 ms with the board off), and about 9 ms when 500 idle units each find only unroutable or ring-blocked jobs, since road routes are searched once per node pair per pass; the SC-10 number is still the reference host's. `World.lost` (node → running tick lost, from `capture`, pruned after the counterattack window) and `World.cooldown` (side → scouted cell → tick) and `World.blob_runs` (side → cell → consecutive SIGINT refreshes a blob kept it, rebuilt by `sense` with the blobs) and `World.intercept_seen` (coalition scout → the Static board pass that first tracked it inside a held node's radius; NX-382 part 2, snapshot format 23) are state too, and `Entity.pickup` is an empty truck's source on its reload step. `SideView` carries every node's `defense_hp` (public node state, FOW-10), so generation reads only the view. Repair-bridge is in code (NX-373 part 2: the coalition's `repair_bridge:<node>` REPAIR_BRIDGE job, its TB-8 resupply dependency and the crew escort; GAMEPLAY §1b, STATE-MACHINES §4.3), and so is the Static's point scout (NX-379) and the coalition's one `retake:<node>` CAPTURE job (NX-475, Q-TD-99..101; GAMEPLAY §1b; a snapshot refuses that key on the Static's board or naming another node, with no new state: the campaign-start holdings are the theater's `start_owner`); its keep after the node's defenses return (NX-484, Q-TD-121, `tasking.retake_keep_min`) reuses `Job.lost` as its clock, already in snapshots and the hash; unclaimed, it never expires by `tasking.expire_min` and a claim starts its CAPTURE clock (`tasking.standing`, Q-TD-121 revised). ### Follow
- **Follow and formation speed (`nexus.core.follow`, NX-374 part 2, NX-369; GAMEPLAY §1b, §5; Q-GP-31..33, Q-SIM-76):** `Entity.follow_id` (the direct leader) and `Entity.fired_by` (`[shooter, running tick]` pairs from `combat`, pruned past `tasking.escort_threat_memory_s`) are state (snapshot format 18; 17 is refused). `steer` runs in the `director` slot after the board, every running tick (never while frozen): it hands followers of a Disabled leader to its leader (`World.remove` does the same for a leader that dies or despawns), finds each armed follower's group threats (a tracked enemy that fired at a group member within the memory, 60 world seconds, or whose kind's catalog weapons reach one; never its live ammo; found per group from a bounding circle on a grid of the side's tracks) and either breaks the follower's station toward the nearest it can hit within `tasking.escort_leash_m` of the convoy (the leader and unarmed followers; a ground unit takes the road leg passing nearest the threat, so BRIDGE nodes are never chosen, and keeps station if none leads closer) or keeps station: a ground follower sets a road path to its leader's destination and a speed cap that closes the road-distance error to its station in one tick (between 0 and its top speed; it may turn back on its road), an aircraft sets a path to the leader's point, wingman point or landing base and uses the ordinary orbit and landing rules. It also fills `World.speed_cap` (m/s before `speed_mult`: station caps and the formation's slowest member, which `movement` applies to ground units only) and `World.group_threat` (armed follower -> threat ids, which `combat` shoots first); both are derived every tick and are neither snapshot nor hash. A snapshot is refused when a follower names a unit that is gone, of the other side, a facility, in a loop, or without the FOLLOW order or an escort claim; a pairing `load` cannot judge without rules (ground after an aircraft) is dropped by `steer`. ### Sensing
- **Sensing (SC-13 `sensing` slot, `nexus.core.fog`, NX-150; FOG-OF-WAR Tier 1, Tier 2, FOW-11, FOW-13):** on ticks where `tick % fow.track_every_ticks == 0`, for each side, every enemy entity inside one of that side's sensors (`sensor.radius_m` × the target's `stealth`, inclusive; no RNG, Q-FOW-2) is tracked, found through uniform grids of the enemy entities, one per sensor range class (SC-10, NX-372): the positive `sensor.radius_m` values ascending, a class spans up to 4× its smallest radius and its cell is its largest radius / 2 (shipped catalog: 3–8 km in 4 km cells, 40–120 km in 60 km cells). Painters paint first, then every sensor tracks, longest first; a target leaves the grids once painted or tracked, which changes no result (both are unions) and cut the SC-10 smoke pass at 1,000 entities about in half. `World.contacts[side]` maps each known enemy id, in id order, to a `Contact{kind, pos, vel, age, painted}`: a tracked one holds the target's values at that pass with `age` null; when a pass no longer tracks it, those values freeze and `age` 0 starts a last-known track, which gains 1 per running tick and is dropped when it reaches `fow.track_fade_s` as world ticks (rounded up), whether or not the entity still exists (FOW-6a); tracking it again replaces it. A facility (STATIC domain) that stops being tracked is dropped instead: facilities never leave last-known tracks; a discovered marker (FOW-13, below) replaces them. `load` refuses a contact whose live entity is on the contact's own side or of another kind. `contacts` is world state (snapshot format 7, `state_hash` with positions in mm and velocities in mm/s). While paused nothing ages and no pass runs (FOW-9, SC-11). Readers use the last pass (Q-FOW-6): `tracked_by(world, side, id)`; `spotted(world, entity)` (FOW-12, derived from the enemy's contacts, not stored); `visible(world, side, entity)`, the FOW-1 predicate (own entities and current tracks; last-known tracks are not visible entities); and `side_view(world, side)`, a `SideView{side, tracks, last_known, nodes, owners, markers, blobs}` (`owners`: every node's live owner, FOW-10, NX-125) of copies that is the director's `EnemyView` for `ENEMY` (FOW-4, FOW-10). **Terrain masking (Q-FOW-3, part 2):** a GROUND target whose 1 km masking cell lies in one or more masking regions is tracked only by a sensor standing in one of those regions; STATIC targets are never masked; NOE and LOW aircraft (`Entity.alt_band`, NX-124 part 3) are hidden by the same rule. No strait-1 road crosses a masking region, so in the shipped theater masking affects only aircraft flying over one; `tests/core/test_fog.py` covers ground and NOE/LOW aircraft masking, with a MED/HIGH control, on a hand-made raster. **Emitters and discovery (FOW-11, FOW-13, part 2):** a dark site (`emitting: false`) has no active or passive coverage. On each pass, a side observes an enemy facility it tracks, or an emitting one within `sensor.passive_range_m` of one of its non-dark passive sensors (no grid: emitters are the few pre-placed sites); observing writes `World.markers[side][id] = FacilityMarker{kind, variant, pos, emitting, confirmed_tick}` (the tick of that pass). A marker is never removed, not even when its entity is; an unobserved site's marker keeps its old values. `load` checks markers like contacts and refuses a `confirmed_tick` after the snapshot's tick. `side_view` carries a copy of the side's markers. **Painted (Q-FOW-6, part 2b):** on each pass a contact gets `painted: true` when a recon unit of the side (RECON_UAV, ENEMY_RECON_UAV) tracks it with its own sensor (its own `sensor.radius_m` × the target's `stealth`, masking included) within `fow.paint_range_m`; another sensor's track does not let it paint. A last-known track is never painted (`load` refuses one). It is stored on the contact, so snapshots and the hash carry it; combat reads it later (COMBAT track quality). The `TargetPainted{recon_id, target_id, until_tick}` event (CONTRACTS) arrives with combat (NX-124), `until_tick` being the next Tier 2 pass. **SIGINT (Tier 1, FOW-2, Q-FOW-5, Q-FOW-7, part 2b):** `World.sigint_age` counts running ticks (not while paused, FOW-9); when it reaches `fow.sigint_refresh_s` as world ticks (rounded up: PROPOSED 54 s is 90 ticks at 6×, 540 at 1×) it resets and each side's `World.blobs[side]` is rebuilt from scratch, after that tick's Tier 2 pass. The inputs are the enemy entities that are not STATIC, have a nonzero velocity on that tick, are not currently tracked by the side, and lie within `fow.sigint_range_mult` × `sensor.radius_m` of one of the side's own RADAR_SITEs that is not dark (FOW-11); masking and stealth do not apply. Q-FOW-7's "moving or emitting": emitting mobile units join when a mobile emitter exists (every emitter today is a facility, FOW-11). Each is counted in the square cell of `fow.sigint_cell_m` it lies in: `(cx, cy) = (floor(x / cell), floor(y / cell))`, each clamped into `[0, bounds / cell − 1]` (a unit on the east or north edge counts in the last column or row), index `cy × (w / cell) + cx`; `make_rules` refuses a `fow.sigint_cell_m` that does not divide both bounds, so every cell, and every blob centre, lies on the map. A `Blob{id, pos, size}` per non-empty cell, in index order: `id` `<refresh_tick>-<cell_index>`, `pos` the cell centre, `size` S below `fow.sigint_size_m_min` units, M below `fow.sigint_size_l_min`, L from there (PROPOSED 3 and 7: S 1–2, M 3–6, L 7+). No entity id, count or exact position, and no RNG draw. `side_view` carries the side's blobs; the director's `EnemyView` gets the same blobs from the enemy's radars (FOW-4). Blob building loops units × radar sites (radar sites are few pre-placed facilities): about 2 ms for one refresh at 1,000 entities in the SC-10 smoke test. Snapshot format 9 adds `painted`, `blobs` and `sigint_age`; `load` refuses a blob id that is not `<int>-<int>`, a side whose blobs mix refresh ticks, one after the snapshot's tick, cells out of order, or a `sigint_age` larger than the ticks since the blobs' refresh. **Base flips (NX-125, FOW-13):** when capture flips a base, each facility of it switches side (`fog.hand_over`): the new owner drops its contact and marker of the facility, since it is its own now, and the side that lost the base gets a marker with the site's values as of the flip tick, so it keeps knowing the site; a facility never leaves a last-known track.

### JOIN
- **JOIN (`nexus.core.handlers`, NX-122):** the kernel's handler table is `nexus.core.handlers.HANDLERS` (re-exported by `nexus.core.step`). Nearest is the straight-line distance for AIR (path `[target]`) and the road-route metres for GROUND, which also needs a road route from the base to the target (ties by node id). The spawn has a FULL loadout (`fuel_s` for an aircraft, Q-SIM-53) and `logistics.loadout_cost.<kind>` leaves the base's stock at spawn with one `SupplyConsumed{node_id, amount, cause: SPAWN}` (CONTRACTS §6; none when 0); `UnitSpawned.node_id` is that base. With no candidate, a null target or `hold`, or a target that is the side's own sanctuary (it spawns there, free), the unit spawns at the sanctuary, which is never a candidate and is never debited. Not in code yet: `ReserveQueueLeft`, milestone position updates (RQ-1), the `slots.queue_idle_min` timeout (runtime, real time), the dynamic cap (RQ-2) and removal on ban or forget.

## 5. Runtime (outside the kernel)

- Threading: the queues are already the boundary, so that is mechanical.
- Restore: the log names only ticks that had commands or a tombstone, so the caller gives the tick to stop at. With no tick given, replay stops at the last tick the log names, so after a process kill a restart resumes there.
- Restore: a replayed tick that raises with no tombstone means the process died after the write-ahead flush but before the tombstone. A tick that raises although it is already tombstoned: restore can't route around it, so it raises at once and needs a code fix.
- Clean shutdown: the weekly maintenance window already pauses with `MAINTENANCE`.
- Command log: For now the runtime flushes every tick (NX-103). SC-8 does not need that: on a `step` exception the runtime appends the tombstone and flushes before it restores, so the buffered commands are on disk in time. Per-tick flushing only shrinks what a process kill loses, so the 1 s cadence is a later optimisation.
